# AcciLessNavi フロントエンド

今回は見た目・画面遷移・ロゴ動画を確認するためのデモです。実データへの接続は行いません。以下のlive接続手順は将来の開発用です。

提供された `AcciLessNaviFront.zip` の画面構成を参考にした React / TypeScript / Vite の実装です。起動とリロードのたびに提供された3秒のロゴ動画を再生し、終了すると画面全体が左にスライドして地点入力を表示します。動画はいつでもスキップでき、再生不可時もフォームへ進めます。

## 起動

Node.js 22.12以上（24推奨）を使用します。

```powershell
cd frontend
npm ci
npm run dev
```

表示された localhost URL を開いてください。Windows PowerShellで `npm.ps1` の実行が制限される場合は `npm.cmd` を使用します。

初期状態は外部API不要のデモです。「現在地を使う（デモ）」で東京駅を設定し、目的地に「上野」と入力して候補を選ぶと比較できます。「つくば」「筑波大学」などの候補もあります。東京〜つくばのように直線距離30kmを超える組合せはAPI契約の範囲外となります。

## 画面と操作

1. ロゴ動画：自動再生 → 左スライド。再生済みフラグは保存しません。
2. 地点入力：候補選択で確定。入力の再編集で確定解除。戻る操作で入力保持。
3. 条件選択：移動手段、出発日時、天気、時間帯、曜日区分、許容追加時間。
4. 結果：左側のサイドバーに比較結果（2つの選定の意味、所要時間〔分・小数1桁〕・距離〔km・小数2桁〕・事故/死傷の件数・天候一致・重み、削減率、選定理由・警告・参考指標の注記、適用条件と出発日時・自動/手動の別、事故点の間引きや注意区間の切り捨ての説明、全候補表）と地点・条件を表示し、ハンバーガーメニューで開閉。経路の時間・距離・追加時間・過去事故件数は地図上の線の近くに黒いカードで表示。事故履歴考慮ルートは緑の線と黄緑のホバー枠、最短時間ルートは青の線と濃い水色のホバー枠で区別します。条件編集と再検索、事故点の詳細表示にも対応。

同じ `/` のReact stateで画面を切り替えます。住所、座標、検索結果をURLやブラウザーストレージへ保存しません。条件変更で古い結果を消し、進行中の要求も中止します。

右下の「デモ状態切替」で、住所候補0件・検索中・エラー・同一経路・事故0件・条件取得不可・地図利用不可を確認できます。検索には中止操作がなく、検索中は地点・条件の編集を受け付けません。「検索中」は他の状態へ切り替えるまで続きます。「条件取得不可」から復旧した後は、更新された条件で「再検索」してください。

デモの経路と事故は架空のデータです。地図は実在道路を示さない模式図、天気は固定値、休日判定は土日と年末年始のみです。実際の移動案内には利用しないでください。

## API仕様との対応

機能と型は、GPSナビ仕様（#2）を含む main の [OpenAPI 2.0](../docs/api/openapi.yaml) を基準にしています。添付デザインに対して次を変更しています。

- 時間帯は早朝04:00–08:59／昼09:00–15:59／夕16:00–18:59／夜19:00–23:59／深夜00:00–03:59の5区分。曜日と出発日時も追加。
- 自動条件と手動条件を区別し、「自動に戻す」に対応。liveでは判定を `/api/conditions` に委ねます。
- デモ住所候補は2文字以上・300ms待機、最大5件。IME変換中は検索せず、↑↓・Enter・Escapeに対応。
- live住所検索は現APIの明示検索契約に合わせ、Enterまたは検索ボタンで実行します。デモと同じオートコンプリートを本番で有効にするには、APIの利用方針を更新してください。
- 全候補の事故が0件なら事故履歴考慮ルートは未選定です。同一経路とは区別します。
- 条件の自動緩和はしません。「条件緩和あり」デモは、現仕様に合わせて「条件取得不可」に置き換えています。
- フロントで実データの重みや優先経路を再計算しません。APIの応答を検証して表示します。

生成型・応答検証は選定経路の `navigation` に対応済みです（未選定はnull、累積距離・区間の相関、5,000,000バイト上限を検査）。ナビ画面そのもの（現在地・接近通知・模擬走行）は未実装です。routeは本文受信から応答検証までを180秒、geocode/healthは45秒、conditionsは10秒で打ち切ります。

フロント画面の実装が今回の範囲です。バックエンド本体、事故データの取り込み、公開先の設定は含みません。仕様書のPWAインストール・オフライン配信と、地図クリックによる出発地／目的地の新規指定は未実装です。

## 実APIと地図への接続

```powershell
Copy-Item .env.example .env.local
```

`.env.local` の `VITE_API_MODE=live` に変更し、開発サーバーを再起動します。開発時の `/api` は `vite.config.ts` で `http://127.0.0.1:8000` に転送します。本番では同一オリジンにAPIを用意してください。APIが利用できなくてもデモへ自動切替はしません。

live の本番ビルドでは、経路・地図提供元の帰属を `VITE_ROUTING_ATTRIBUTION`・`VITE_MAP_ATTRIBUTION` で渡します（どちらも必須）。未設定の場合はデータの出典欄に「帰属表示が未設定です」と表示します。事故・気象・祝日データの帰属と、住所検索応答の `attribution` は常に表示します。結果画面では、サイドバーを閉じても地図の下に表示されます。

検索の失敗は `error.code` ごとに案内します（400 の直線距離30kmと経路長80kmの区別、422、502 `no_route`／`external_api_error`、503、タイムアウト）。リダイレクトされた応答と401/403は `auth_required`、それ以外のJSONでない応答（HTMLのエラーページを含む）は `invalid_response` とし、どちらもページの再読み込み（再ログイン）を案内します。このビルドが知らない `error.code` は、サーバーの説明文に再試行の案内を添えて表示します。health・住所検索・条件取得の失敗も同じ規則で案内します。ブラウザーでは認証リダイレクトが通信エラーに見える場合があるため、通信エラーの案内にもログイン切れの可能性を含めます。

実地図には `VITE_MAP_STYLE_URL` にMapLibre用スタイルURLを設定します。未設定時は模式図になります。地図利用不可でも経路比較は閲覧できます。利用するスタイル・タイル配信元の帰属と公開可能なキーを設定してください。`VITE_` の値はブラウザーに公開されるため秘密鍵は入れません。

liveの現在地ボタンを押した時だけブラウザーの位置情報を要求します。初回表示で要求せず、失敗時は住所入力へ戻れます。

## 開発・検証

```powershell
npm run generate:api  # docs/api/openapi.yamlから型と検証schemaを生成
npm run typecheck
npm test
npm run build
```

`src/api/generated/` は生成物です。契約を変更したときは生成し直してコミットしてください。OpenAPIと相関制約による応答検証、要求の中止、入力候補、IME、条件の競合、事故0件、同一経路、動画の再マウントをテストしています。

API 2.0の実サーバーと地図配信元はこのリポジトリに含まれないため、実データでの結合確認は別途必要です。今回の環境ではブラウザー連携のURLポリシーで画面取得が拒否され、デスクトップ／モバイルの目視確認は未実施です。ビルド、自動テスト、トップページと動画のHTTP配信を確認しています。

## 主なファイル

- `src/App.tsx`：画面遷移と、各状態・API操作の調整
- `src/state/`：UI描画から分けた状態管理（`useHealth`＝health と dataset_id の照合、`useConditions`＝出発日時と条件の自動/手動・世代管理、`useRouteSearch`＝検索の世代・結果と要求時の入力、`useCurrentLocation`＝GPSによる出発地）
- `src/components/`：地点・条件・比較（`ResultsPanel`）・データの出典（`DataAttribution`）・地図・動画
- `src/api/errorMessage.ts`：`error.code` から利用者向けの案内文を作る処理

構成の方針：architecture 2章の構成案のうち、状態管理は `src/state/` を新設しました。ナビは `src/navigation/`、地図の source/layer 定義とスタイルアダプタは `src/map/` に新設する予定です。画面部品は既存の `src/components/`、API は `src/api/`、表示変換は `src/lib/` に置きます。CSS変数のデザイントークン層は `src/styles.css` の `:root` に集約します（地図用のアダプタは `src/map/` で同じトークンを読む予定）。
- `src/api/`：実APIクライアント、デモ、応答検証
- `src/api/generated/`：OpenAPI由来の型とJSON Schema
- `public/assets/acciless-navi.webm`：提供されたロゴ動画の原本
- `public/assets/acciless-navi-poster.jpg`：動画から作った白背景の静止画

添付ZIPのNext.js構成や分析SDKは取り込まず、画面の構成・余白・カード操作を参考にしています。
