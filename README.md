# AcciLessNavi
**過去の交通事故データをもとに、「最短ルート」と「事故履歴を考慮した安全ルート」を並べて比較できる経路提案アプリです。**

![AcciLessNavi](./assets/AcciLessNavi_bordered.gif)

## 製品概要

### 背景（製品開発のきっかけ・課題等）

普段使っている地図アプリは「いちばん早く着く道」を案内してくれます。けれども、その道が過去に事故の多かった交差点や見通しの悪い道路を通っているかどうかは、通常の地図を見てもわかりません。

警察庁は、全国の交通事故の発生場所・日時・天候・死傷者数などを「交通事故統計オープンデータ」として公開しています。ところが、このデータは一般の利用者がそのまま日常のルート検索に使える形にはなっておらず、日々の経路選びには十分に活かされていません。

「数分の遠回りで事故の起きにくい道を通れるなら、そちらを選びたい」と考えたときに、自分の移動状況に合った判断材料を手軽に得られる手段をつくりたいと考え、本プロダクトを開発しました。

### 製品説明（具体的な製品の説明）

**AcciLessNavi** は、出発地と目的地を入力すると、次の2つのルートを地図上に並べて表示・比較できるWebアプリケーションです。

- **最短ルート**：取得した経路候補のうち、所要時間がもっとも短いルート
- **安全ルート**：許容できる遠回りの時間内で、指定した移動条件における過去の事故リスク（重み）がもっとも小さいルート

使い方はシンプルな3ステップです。

1. **出発地と目的地を設定**：住所・駅名・施設名で検索するか、「現在地を使う」からGPSで出発地を設定します。
2. **移動条件を設定**：移動手段（徒歩・自転車・自動車）、出発日時、天気、時間帯、曜日区分、許容できる遠回りの時間（0〜30分）を選びます。時間帯・曜日区分・天気は出発日時と地域から自動で設定され、手動で変更することも可能です。
3. **ルートを比較**：地図上のカードで、2つのルートの所要時間・距離・追加時間・過去の事故件数を見比べながら、納得して経路を選べます。

事故の重み（リスクスコア）は、移動手段・時間帯・曜日区分が一致する過去の事故を対象に、次のロジックで算出します。

- ルートから約72m以内の事故を対象とし、ルートに近い事故ほど重く評価する
- 死者1人を負傷者10人分として換算し、事故の深刻度を重みに反映する
- 雨・霧・雪を指定した際は、同じ天候で起きた事故をさらに重く評価する（雨：2倍、霧・雪：4倍）

### 特長

#### 1. 移動条件と「遠回りの許容時間」から最適な道を選べる

**過去の事故地点を一律に表示する既存の安全マップとは異なり、**「徒歩・自転車・自動車」や「天候・時間帯」といった利用者自身の移動状況に即した比較ができます。さらに「何分までなら遠回りできるか」を指定すると、その範囲内で事故の重みが最小となるルートを提案します。

#### 2. 出発日時から時間帯・曜日・天気を自動で設定

時間帯は5区分（早朝・昼・夕・夜・深夜）、曜日区分は平日・休日（祝日・振替休日・年末年始を含む）で判定します。天気は Open-Meteo の現況・予報データから自動で取得します。将来の日時を指定すれば、事前の移動計画でも「その時刻・その天気」における事故傾向でルートを比較できます。自動設定された値は、いつでも手動で変更可能です。

#### 3. 現在地からのGPSナビゲーション

選択したルート上で、現在地の追従・残り距離と所要時間の表示・事故多発区間への接近通知を行うナビ機能を搭載しています。実機のGPSとデモ用の模擬走行は共通の判定エンジンで動作し、往復や折り返しのような複雑な経路でも誤った位置を確定しないようにしています。

### 解決できること

- 経路を選ぶ際に「速さ」だけでなく、過去の事故履歴という客観的なデータを判断材料として手軽に活用できます。
- 通勤・通学や初めて訪れる土地での移動前に、ルート周辺で過去にどのような事故が発生していたかを把握し、遠回りの時間的負担と比較しながら納得して道を選べます。
- 徒歩・自転車・自動車など、移動手段によって異なる事故の発生傾向や注意すべき箇所を比較・把握できます。

### 今後の展望

- 実データおよび外部サービスを接続した本番環境へのデプロイ（Cloud Run＋IAP)
- 事故の重み付けパラメータを、より多くの経路・年度データで検証し精緻化する。
- 交通量や歩行者数などのデータを掛け合わせ、事故件数だけに依存しない評価指標を検討する.

### 注力したこと（こだわり等）

- **仕様とスキーマを先に固め、テストで守る開発**：OpenAPI 3.1から型と検証スキーマを自動生成しています。バックエンドとフロントエンドが同一の応答例を通過することをテストで検証しています。
- **検索条件を自動設定しつつ手動で上書きできる** 出発日時から時間帯と天候を自動で設定するので、利用者は条件を選ばなくても検索できます。手動で選んだ条件は自動取得で上書きされず、出発日時を変えたときだけ自動設定に戻ります。
