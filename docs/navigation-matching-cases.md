# 現在地と経路の照合の受け入れケース

利用者決定に基づき、[frontend-spec.md](frontend-spec.md) 7.3の条件を実装時に検証する。入力の生成方法と出力の許容範囲を規定し、照合の計算手順・内部表現は規定しない。各ケースは実装時の必須試験であり、今回の仕様書編集で共通判定器の合格を確認したものではない。

## 共通の入力と判定

- 時刻tは開始を0とした仮想秒。特記しなければmode=car、accuracy=10m、t=0の初回と以後1秒間隔で測位する。各行を揺らぎOFF/ON、seed=1/2/3/42、倍率1/2/4/8の全組合せで実行する。OFFでもseedを同様に進める。倍率によらず同じ仮想時刻の結果が一致すること。
- 人工経路は局所平面の東西軸x（m）、南北軸y=0で定義する。緯度35度、x=0を経度139度とし、`lon=139+x/(6371008.8*cos(35*π/180))*180/π`、`lat=35+y/6371008.8*180/π` で変換する。累積距離は折返しも正の辺長として加算する。既存の往復は [api/fixtures/navigation-cases.json](api/fixtures/navigation-cases.json) のgeometryを共用する。
- 入力生成はfrontend-spec 7.7のLCGと半径8mの揺らぎに従う。t=0でも最初の2乱数を使い、終点保持中も各tickで2乱数を進める。欠測注入は生成した入力を渡さない操作とし、乱数・仮想時計は進める。精度値の変更は揺らぎの半径を変更しない。一時停止中は時計・乱数とも進めない。
- 通常走行では真の進捗 `p_true=min(L,L*t/duration)` から基準位置を生成し、終点後はその位置を保持する。引き返し等は各行の移動で置き換える。判定器へ渡すのは `{lon,lat,accuracy,timestamp}` と時計だけ。p_true、入力種別、seed、既知の終点時刻、将来の測位は渡さない。経路とナビ用データは通常の開始時と同じものを渡す。
- 真の進捗を持つ入力では、**全確定時点で `abs(p−p_true) <= max(20m,2*accuracy)`** を検査する。到着による表示の0への置換前に判定する。更新停止と時点を示した旧値の保持は新たな確定に数えない。範囲外の確定は1回でも不合格。近い位置でも識別未了の進行方向で接近通知を出さない。
- 表の時刻範囲は両端を含む。到着の時刻範囲だけでなく、frontend-spec 7.3の初回/再確認3測位・5秒と7.4の到着条件を満たすこと。確定前・精度不足・保留・逸脱中は接近通知/到着が0件。初回/再確認の時間を到着の5秒へ二重に算入しない。各行の保留期限を超えて止まり続ける方式は不合格とする。
- 通知の抑止は、往復では既存fixtureのsections、それ以外では試験用に距離軸上の `[0,min(300,L)]` を1区間としたナビデータでも確認する。保留中に通知済み扱いで消費せず、確定後はfrontend-spec 7.5の通知/通過規則に従う。通知・逸脱・精度の既存暫定値は変更しない。

M1/M2の揺らぎOFFの到着上限は既存の「終点後6秒以内」を維持する。揺らぎONは終点後15秒の停止期限より前（終点後14秒まで）を必須とし、正常入力を停止規則で打ち切るだけの実装を認めない。到着の下限は早着を許すための値ではなく、7.4の継続条件と併せて検査する。既存fixtureの固定到着時刻・内部状態の期待はこの範囲への置換対象で、ナビ区間の数値期待値は変更しない。

実機でもM6/M7と同じ位置入力では進捗・通知・到着を保留し、理由と停車後の明示再開/再検索/終了を示す。ただし終点時刻を知らない実機へ模擬の自動停止期限を適用しない。その他の精度30m/30m超、鮮度5秒/5秒超、30秒ちょうど/超の中断、通知・逸脱・到着の境界はfrontend-spec 11章も検証する。実機のGPS精度や任意の道路形状への適用性は、これらの人工ケースの合格とは別に記録する。
