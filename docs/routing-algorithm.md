# 事故リスクを考慮した経路探索の仕組み

この文書は、M5 の時点の自前の経路探索（以下、新方式）がどう動くかを、コードを読まない人にも分かるように説明します。読み手として、リポジトリを見る人と PR のレビュアーを想定しています。細かい仕様と数値の根拠は `docs/routing-plan.md`、`docs/routing-exposure-plan.md`、`docs/routing-reports/M5.md` にあります。

## 1. どういうアルゴリズムか

新方式は「遠回りの上限の中で、過去の事故から推定したリスクが最も小さい経路」を探します。利用者が許す遠回り（たとえば10分）を超えない範囲で、事故の起きやすい道路や交差点をなるべく避けます。

処理は前もって作っておく部分と、経路を問い合わせるたびに行う部分に分かれます。

| 段階 | いつ | 内容 |
|---|---|---|
| 道路のグラフ | 前もって | OSM から、徒歩・自転車・自動車の共通の道路網を作る |
| 事故の割り当て | 前もって | 警察の事故データの1件ずつを、道路の区間と交差点に割り当てる |
| リスクの推定 | 前もって | 区間と交差点ごとに、事故の起きやすさを推定する |
| 経路の探索 | 問い合わせのたび | 遠回りの上限の中でリスクが最小の経路を探す |

### 道路のグラフ

全国の OSM から、3つの手段で共通の道路網を1つ作ります。全国で約1,476万ノード、2,003万辺です。辺ごとに、徒歩・自転車・自動車のどれが通れるか、一方通行かを持たせます。右左折禁止も守り、信号や右左折にかかる時間を所要時間に入れます。

### 事故を道路に割り当てる

旧方式（OSRM候補）は経路から72m以内の事故を円の範囲で数えます。この数え方では高架の下の一般道や隣の道路の事故まで混ざります。新方式は事故の1件ずつを、実際に起きたと考えられる道路の区間か交差点に割り当てます。

- 交差点で起きた事故は、30m以内の交差点のまとまり（交差点クラスタ）に割り当てます。
- 単路で起きた事故は、35m以内の車道の区間を候補にします。距離に加え、事故データの路線コード（国道・県道・市町村道・高速道路など）とOSMの道路種別の合い方、国道番号、幅員・橋・トンネルとの整合から、もっともらしさを計算します。そのうえで、最大3本の候補に重みを分けます。
- 高速道路の事故は高速道路の区間にしか割り当てません。
- 1件の事故の重みの合計は1以下にします。同じ事故を2本の道路で二重に数えないためです。どこにも当てはまらない事故は、無理に割り当てずに「帰属不明」として残します。

### 区間ごとのリスクを推定する

割り当てた件数をそのままリスクにすると、偶然に振り回されます。事故が0件の区間は完全に安全とみなされ、死亡事故が1件あるだけで大きな値になります。新方式は道路安全の分野で使われる方法で、この偶然のぶれを抑えます。

1. 種別から見た期待件数：道路の種別（道路の種類、幅、人口集中地区かどうか）ごとに、長さあたりの平均の事故件数を求めます。区間の長さを掛けると、「この種類の道路なら、この程度は起きる」という期待件数になります。交通量を使わない、事故件数の予測式（SPF）にあたります。
2. 経験ベイズ：区間で実際に観測した件数と、種別から見た期待件数を、重みを付けて混ぜます。観測の少ない区間ほど期待件数に寄せます。これで、事故0件の区間にも小さな正のリスクが付き、1件の偶然で値が跳ね上がることもなくなります。
3. 深刻度：`10×死者+負傷者` の重みは区間ごとではなく種別ごとの平均を掛けます。区間ごとの死亡事故1件の偶然に振り回されないためです。
4. 条件：時間帯（5区分）と曜日（平日・休日）ごとにリスクを持ちます。雨・霧・雪を指定したときは、同じ天候の事故を重く数えます（雨は2倍、霧・雪は4倍。旧方式の倍率を引き継いでいます）。
5. 道路区分の係数（自動車だけ）：幹線道路は交通量が多いので、事故の件数も多くなります。件数だけで比べると、件数の少ない生活道路へ回り込む経路を選びがちです。そこで、国交省が公表している区分別の事故率（走行台キロあたりの件数）を使い、交通量の違いを区分ごとに補います。本番の係数は自動車専用道路0.246、幹線1、生活道路14.85です。生活道路の事故1件は幹線の約15倍に数えます。

係数は区分ごとに「事故件数 ÷ 道路の延長 ÷ 事故率」を計算し、幹線との比をとって決めます。この係数は所要時間には掛けません。徒歩と自転車にも掛けません。車の交通量は、歩行者や自転車がどれだけ通るかを表さないためです。

### 遠回りの上限の中で経路を探す

問い合わせが来るたびに、次の順で経路を探します。

1. 最短時間の経路を求めます。この所要時間に遠回りの上限を足したものが、時間の上限になります。
2. 楕円の切り出し：「出発地からの時間＋目的地までの時間」が上限以下になる道路だけを残します。上限を守れる経路は必ずこの範囲を通るので、範囲の外は探さなくて済みます。
3. LARAC：「所要時間＋λ×リスク」が最小の経路を、λを変えながら10回求めます。上限を満たす良い経路と、リスクがこれより小さくはならないという下限が得られます。
4. RCSP：時間とリスクの両方を持つ探索で、上限の中でリスクが最小の経路を探します。LARAC の経路を出発点にし、2,000ms の時間予算の中で改善します。予算の中で探索が終われば、このグラフとリスクのもとで最適です。終わらなければ、それまでの最良の経路を返します。
5. 候補の整理：最短時間の経路 `p0`・リスク最小の経路 `best`（および中間案 `middle`）は重なりによる除去の対象から外し、それ以外の候補（LARAC の途中で得た経路など）について、重なりが80%を超えるものを除いて最大6本を返します。すべての候補が時間の上限を守っているかを、最後に確かめます。

LARAC だけで終えないのは、「時間＋λ×リスク」の形では上限の中の最適な経路を取りこぼすことがあるためです。

楕円が大きすぎる場合（30万ノードを超える場合）は、出発地と目的地の近くを除いて幹線以上の道路だけで探し直します。それでも大きすぎれば、最短時間の経路だけを返します。

API とフロントエンドは変えていません。今の契約の範囲で、新方式の値を返します。画面ではリスクを「過去の事故に基づく推定指標」として扱い、事故の確率とは呼びません。

## 3. どのように改善したか

### 旧方式（OSRM候補）の問題と、新方式での対処

旧方式（OSRM候補）はOSRM が返す数本の候補のうち、経路から72m以内の事故の点数が最も低いものを選びます。

| 旧方式（OSRM候補）の問題 | 新方式での対処 |
|---|---|
| 円の範囲で数えるので、並行する別の道路の事故まで数える | 事故の1件ずつを道路の区間と交差点に割り当て、二重に数えない |
| 候補は OSRM 任せで、リスクの低い経路を自分で探していない | 自前の道路網で、遠回りの上限の中でリスク最小の経路を探す |
| 偶然の変動に弱い（事故0件の区間を完全に安全とみなし、死亡事故1件で点数が大きく増える） | 経験ベイズで件数を縮め、深刻度は種別ごとの平均を使う |
| 件数だけで比べるので、自動車が生活道路へ回り込む | 国交省の区分別の事故率で、自動車の区分ごとに係数を掛ける |

最後の行はM5 で入れたものです。計画では生活道路にだけ係数 c を掛けて回り込みを抑える予定でした。ところが c を1から6まで変えても生活道路を走る割合はほとんど減らず、100まで広げても決め方の規則で値が定まりませんでした。そこで利用者の承認を得て、道路区分ごとの事故率で補う方法に置き換えました。

### 開発の中で調整した値

| 項目 | 決めた値 | 決め方 |
|---|---|---|
| 事故の位置の誤差（σ0） | 3.5m | 2・3.5・5・7m で比べ、削減率の差が0.5ポイント以内だった |
| 高リスク区間のしきい値（区間を高リスクとして示す事故件数） | 3件 | 2件にすると、自動車の経路で区間が多くなりすぎる |
| 探索の時間予算 | RCSP 2,000ms、LARAC 10回、楕円30万ノード | 自動車の処理時間の99%点が10秒以下の組み合わせのうち、RCSP が最後まで終わる割合が大きいもの |

### 効果

東京23区・千葉市・さいたま市・横浜市の1,200組で、2019〜2023年の事故で学習し、2024〜2025年の事故で、最短時間の経路と比べた削減率を測りました。遠回りの上限は10分です。徒歩と自転車は事故の件数で、自動車は区分の係数で重みを付けた件数で測りました。

| 手段 | 新方式 | 旧方式（OSRM候補） | 新方式の追加時間の平均 |
|---|---|---|---|
| 徒歩 | 53.6%減 | 13.8%減 | 8.3分 |
| 自転車 | 53.9%減 | 1.8%減 | 9.0分 |
| 自動車 | 60.7%減 | 24.0%増 | 9.2分 |

要素を1つずつ外して比べると、経験ベイズを外せば徒歩の削減率が13ポイント下がり、交差点クラスタを外せば徒歩で8ポイント、自転車で4ポイント下がりました。

全国と関東の1,800組では、逆走や通れない道を通る違反は0件でした。自動車の処理時間は、99%が8.2秒以内でした。

### 残っている弱点

- 遠回りの上限の近くまで使います。上限を5分にすると、追加時間は4.4〜4.7分になり、削減率は徒歩50.2%、自転車49.0%、自動車（重み付き）56.9%です。
- 自動車でも、生活道路を走る割合は4.9%から24.2%に増えます。徒歩は46%から61%、自転車は46%から71%です。徒歩と自転車には通行量のデータがないので、件数が少ないのが通る人の少なさのせいか、本当に安全なせいかは区別できません。
- 自動車の評価は国交省の事故率を交通量の代わりとして正しいとみなす前提に立っています。この重みは経路を選ぶときにも使っているので、独立した検証にはなりません。件数だけで測ると、自動車の削減率は36.4%です。
- リスクから予測した事故の件数は、実績より少なく出ます。自動車で約1.2倍、徒歩・自転車で約2倍の差があります。画面の値は経路どうしを比べる相対的な値として扱う必要があります。
- 評価したのは関東の都市部の4地域だけです。農村・山間部・積雪地での経路の質は確かめていません。
