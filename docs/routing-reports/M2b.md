## 3. 推測で決めた点

1. 交差点（道路形状1・31）の事故は、30m以内のクラスタがあればクラスタだけに配分し、なければ辺に進む。交差点付近・単路・踏切は辺に配分する。
2. 番号の照合は国道だけ。主要地方道・一般県道の路線コード上4桁は通し番号で、県道番号と一致しないことを実データで確かめた（一致は36〜40%）。
3. 双子は1組の候補として扱い、近い方の辺に重みを載せ、もう一方に `MIRROR` で写す。
4. 0.1未満を捨てた後に再正規化しない（合計は1以下）。
5. 重みの不足（理由3）が0件になった。正規化だけで配分するため、遠い候補でも重みが残る。「どの候補でもない」という仮説を足す方法があるが、仕様から外れるので入れていない。人の確認の結果で判断する。
6. `PARAMS` の構造（`rules_version: "jp-assign-1"`、尤度表など）は作業役が決めた。形式書13章への追記が必要。
7. 索引 `EdgeAccidentIndex` は約145MBで、形式書17章の見積もり（70〜100MB）より大きい（辺の開始位置の表が約81MB）。M4のメモリの見積もりに反映する。

## 4. 人の確認の手順

1. `data/work/M2/review/index.html` をブラウザで開く（`file://` で動く。外部への通信は、OSMの地図タイルとLeaflet 1.9.4の取得だけ）。
2. 200件（19層：道路種別6×道路形状3の18層と、一般交通の場所6件）を1件ずつ見る。青い点が事故の位置（35mの円つき）、色付きの線・点が候補（薄い黄が重み0.1、濃い赤紫が1.0、点線は双子への写し、灰色は選ばなかった候補）。ページの先頭に判定の基準がある。
3. 「正しい」「誤り」「判断できない」を押す（キー1・2・3、←→で移動）。判定はブラウザ内に保存される。
4. 「CSVを保存」で `judgments.csv` を保存し、`data/work/M2/review/judgments.csv` に置く。
5. 指示役が、最大の重みが0.8以上の群とそれ以外の群に分けて正解率を集計し、この報告に追記する。0.8以上の群が85%を下回れば、誤りの傾向を分析し、作り直すかを相談する。

注意：作業役の環境にはブラウザがなく、見た目は実際のブラウザで確かめていない（jsdomと実物のLeafletで、描画・操作・保存・CSVを確認した）。
