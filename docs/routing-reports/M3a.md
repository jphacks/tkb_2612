## 3. 難所の確認（指示役がコードを読んで確かめた点）

1. **楕円の枝刈りが、実行可能な経路を落とさないこと**：確認した。
   - 前向き・後ろ向きの探索（`ellipse.rs` の `cut`）は、キー（`g + h`）がBを超えるものだけを打ち切る。`Half::relax` は閉じたノードの再オープンを許すので、下界がわずかに無矛盾でない場合（ALTの量子化）でも距離は収束する。
   - 下界 `h` は許容的（実際の値以下）である。そのため、辺の時間の和がB以下の経路上の各ノードは、前の頂点が正確な値で取り出されたときに、正確な値で更新される。
   - `keep` は最終的な `df`・`db` で判定するので、その経路の各有向辺は `df(u)+t(e)+db(v) ≤ B` を満たして残る。右左折禁止とコストは時間を増やすだけなので、上限を満たす経路は辺の時間の和もB以下である。
   - 後ろ向きの探索は、`out_dedges(v)` の各 `d` について `d.reversed()`（u→v）をたどっており、向きは正しい。
2. **RCSPの優越判定で、状態が異なるラベルどうしを比べていないこと**：確認した。
   - 非劣解の集合は状態ごと（`frontiers[state]`、`rcsp.rs` の `insert_label`）に持つ。状態は `StateSpace::intern` が「局所ノード、直前の有向辺、照合器の状態」で番号を振る。
   - ラベルの延長は状態の遷移（`space.transitions`）に従い、右左折コスト・ノードの加算・禁止・通過不可は遷移に含まれる。
   - 作業役は、状態から直前の辺や照合器の状態を落とす変異で、試験が失敗することを確かめている。
3. **中断と時間予算で打ち切ったとき、最良解を返し、最適と記録しないこと**：確認した。
   - 時間予算かラベル数の上限で止まると `stopped_early` が立ち、暫定解を `Bounded` で返す（gapは残りのラベルのリスクの下界から計算）。
   - `Optimal` になるのは、到着の状態のラベルを取り出したとき（下界が無矛盾なので辞書順で最小）か、打ち切らずに探索を尽くしたときだけ。
   - 暫定解がないまま止まった場合は、最短時間経路を `FastestOnly` で返す。
   - 中断（`CancelToken`）は `Interrupt` を返し、部分的な結果を返さない。

気づいた点（不具合ではない）：枝刈りの `f_time > bound` は、直前の `time > bound` と `to_time` を足した判定で、正しさに影響しない最適化である。

## 4. 推測で決めた点、骨組みから変えた点

シグネチャの変更（M0の報告で、M3aが詰めてよいとした範囲）：

| 変更 | 理由 |
|---|---|
| `ArcCost` に `partial_risk_fx(d, from_dm, to_dm)` と `cluster_entry_risk_fx(d)`（既定0）を追加 | 出発・到着の部分辺のリスクと、交差点クラスタの加算を探索の外から与えるため |
| `SearchParams` に `rcsp_label_limit`（既定2,000,000）を追加 | ラベル数（メモリ）の上限のため |
| `ellipse_subgraph`・`reduced_ellipse` に `cost: &mut dyn ArcCost` を追加 | `SubArc.risk_fx` を付けるため |
| `larac(ctx, sub, iterations, cancel)`。`LaracResult` を作り直し、`HullPoint` は廃止 | 探索に `ctx.graph`・`ctx.automaton` が要るため。凸包の途中解を経路ごと持つため |
| `bounded_rcsp` は `Result<Option<RcspResult>, Interrupt>` を返す | `None` は到着へ届かない場合 |
| `overlap_ratio`・`select_candidates` に `topology` などを追加 | 双子の辺の判定と、p0・bestを区別するため |
| ALTの直線距離の安全率を `fastest::STRAIGHT_FACTOR`（0.8）に揃えた | 下界を許容的にするため |

推測で決めた点：
1. 縮小の「3km以内の辺」は、辺の始点か終点が、出発・到着の吸着点から直線距離3km以内の辺とした。
2. `search_subgraph` は、LARACでリスクの最適性を確認できたらRCSPを省く。その場合、同じリスクの解のうち時間が最小のものまでは保証しない。
3. 重複の判定の分母は、比べる側（後ろの候補）の長さ。80%ちょうどは残す。
4. 縮小でも `TooLarge` のときに最短時間経路だけにする分岐は、M3b.4の結合で組み込む。

## 7. 追記：双子が多対多になったことへの対応（2026-11-03）

`feat/routing-m1` の「双子の多対多化」（`jp-topology-2`、`docs/routing-reports/M1.md` 6章）を `feat/routing-m3a` にマージし、候補の重複判定（`search/candidates.rs`）を合わせた。

- `Topology::twin_of`（1本）が `twins_of`・`are_twins` に変わったので、`overlap_ratio` は「経路 `b` の区間の辺が、`a` の区間の辺と同じ、または双子（`are_twins`）か」で判定する。
- 双子の区間の写し方を変えた。以前は、双子の辺の区間を、辺の長さの比で比例させて写していた（双子の辺が同じ区間に並走することが前提）。多対多では、長い1本の反対側が短い複数の辺に分かれたり、片方が一部にしか並走しなかったりするので、`map_twin_interval` は区間の両端の点を辺の折れ線に投影して、辺のどの区間に当たるかを求める。辺の端の外側に当たる部分は端に丸めるので、並走しない部分は共有に数えない。向きが逆でも同じ規則で写る。1対1で同じ長さの双子では、以前と同じ結果になる（既存の試験が通る）。
- 試験を足した（`tests/routing_search.rs` の `many_to_many_twins_count_only_the_stretch_they_run_alongside`）：長い1本と短い3本の双子で、短い辺は自分の長さの全部、長い辺は3分の1ずつが重なる。短い辺どうしは重ならない。部分的な区間は、並走する長さだけが共有になる。双子でなければ重ならない。`select_candidates` が、長い辺と、それと並走する短い辺の列を同じ候補として捨てる。

重複の判定のしきい値（80%超で捨てる）、分母（比べる側の長さ）は変えていない。
