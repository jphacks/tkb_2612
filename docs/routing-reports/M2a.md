## 3. 年によって違う列とコード

- 列数は2019〜2021年が58列、2022〜2025年が68列。列名で引くので位置は固定しない（位置は `audit.json` の `years.<年>.column_positions`）。
- 車道幅員は2022年だけ、交差点の区分を別のコード（12・13・16）で表している。2024年のコード（14・17・18）へ写す。この写しは2022年の行にだけ適用する。
- 路線コード・道路形状・歩車道区分・地形は全年同じコード集合。2022〜2025年はXLSXのコード表と毎回照合する。2019〜2021年のPDFは既存の方針どおり存在とSHA-256の記録だけ（作業役が `pdftotext` で内容を手元で確認）。
- 実データの欠損・未知コードは、全年・全属性で0件。

## 4. 推測で決めた点

1. 欠損と未知は `.bin` では同じ値（`0xFF`・`0xFFFF`）にし、監査では分けて数える。
2. 路線コードは「ASCII数字ちょうど5桁」だけを有効とする。上4桁が区分表にない場合は、上4桁・下1桁は読んだ値のまま、路線区分だけ `0xFF`。
3. `PARAMS` のキー構成（`rules_version: "jp-attrs-1"` など）は作業役が決めた。形式書12章は中身を「年ごとの列とコードの扱い、欠損・未知コードの件数」としか書いていない。
4. `decode_accident_attrs` は、件数に加えて各レコードがコード表の値か欠損値であることを検査する（形式書12章に読込時の検査の記述がないため追加）。
5. 作り直した事故CSVのgzipが、releaseのものとバイト列で違っても、展開した内容が同じなら進む（`gzip_identical: false` を記録）。今回の実データでは一致した。
