## 3. 推測で決めた点、計画書から外れた点

利用者の確認を特にお願いしたい点に★を付けた。

1. ★**所要時間モデル `jp-time-2`**（`prep/time_defaults.rs`）：自前の経路の特徴量（種類別の距離、信号・一時停止の数、右左折の数）をOSRMの所要時間に非負最小二乗で回帰した。値はOSRMのcarプロファイルに近づいた。
   - 速度：motorway 89、trunk 83、primary 63、secondary 54、tertiary 41、residential 26.5 km/h。
   - 加算：信号2秒、一時停止1秒、右折7.5秒、左折3秒。
   - 徒歩・自転車は変えていない（walk 4.8km/h・信号15秒、bike 15km/h・信号10秒）。OSRMとの差は、信号の待ち時間の仮定が主な原因である。
2. ★**辺の分割点**：信号などのノードとviaノードでも辺を分割した。plan2の数え方と違う。
3. ★**吸着可能な辺の規則**：M1.8で見つけた不具合を直した。障害物ノードに囲まれた小さな領域の辺が吸着可能になっていて、そこへ吸着すると到達できない探索が全国を調べ尽くし、自動車で約40秒かかっていた（サーバの期限は35秒）。
   - 新しい規則：強連結成分を、その手段で通過できないノードを通り抜けられないものとして求める。障害物を端点に持つ辺は、もう一方の端点が大きな成分にあれば吸着可能のままにする。ただし、両端が障害物の辺と、一方通行の辺は除く。
   - 吸着可能な辺は、carで49,648本（0.32%）減った。
   - 形式書10章への追記が必要である。
4. **双子・歩道の親・クラスタのしきい値**は推測で、正解データでは確かめていない。
   - 双子：同じref/name、間隔60m以内、逆向き、重なり60%以上。
   - 歩道の親：15m以内、方位差20°未満。
   - クラスタ：20m。
5. **通行規則の細部**（`vehicle=yes` の扱い、`bicycle=yes` で階段も自転車可など）は、形式書7章を文字どおりに読んで決めた。`graph::rules` のテストに表の各行がある。
6. **`graph_attrs.bin`** に `NODEID` 節を足した。STRTABの添字はバイトオフセットである。
7. **依存の追加**：`osmpbf = "0.3"` と `rayon = "1"`。`cargo update` はしていない。③の担当者の確認が必要である。
8. **ODの作り方**：吸着可能な辺から一様に出発点を選び、手段ごとの距離帯（walk 0.3〜3km、bike 1〜10km、car 2〜30km）で目的地を選んだ。辺の数で一様なので、都市部が多くなる。
9. **作業書との違い**：M3aは、M1の基盤に依存するため、`feat/routing-m0` ではなく `feat/routing-m1` から切った。

## 6. 追記：上下線の双子を多対多にした（2026-11-03）

`find_twins` は「お互いが最良の相手である1対1の組」だけを採用していた。片方の車線が長い1本で、反対側が短い辺に分かれていると、組になれるのは1組だけで、残りの辺に双子がなかった（本線の一方通行の辺の33.5%）。判定と照会を、次のように直した。形式（バイト配置）は変えていない。

- 判定（規則の版 `jp-topology-2`。`topology.bin` の `PARAMS.rules_version`、`config.twin_rule = many-to-many-overlap-v2`）：条件（逆向き・一方通行・同じref/name・間隔60m以内・方位差30°以内・並走）を満たす逆向きの辺はすべて双子にする。1つの辺に双子は複数ありうる。
  - 並走の長さ：短い方の辺（同じ長さなら番号の小さい辺）に5mおきに点を取り、長い方の折れ線から60m以内で、進行方向が逆向きで、最寄りの点が長い方の端の外側にはみ出さないものの割合に、短い方の長さを掛ける。並走の長さが「短い方の長さの6割」と30mの小さい方以上なら双子にする（新しい値 `twin_min_overlap_m`）。
  - 前の版との違い：点は20mおきから5mおきに、長い方の端の外側の60m以内も並走に数えていたのをやめた、1対1をやめた、30mの下限を足した。端の外側を数えると、多対多にしたとき、端でつながるだけの向かい合う辺（交差点の両側）まで組になってしまうため。
- `Topology` の照会：`twin_of` をやめ、`twins_of(e)`（双子の辺の列、昇順）・`twin_records(e)`・`has_twin(e)`・`are_twins(a,b)` にした。`validate` と `decode_topology` は、`TWIN` が `(a,b)` の辞書順の狭義昇順で、`(a,b)` があれば `(b,a)` もあることを確かめる（前は `a` の狭義昇順）。
- 利用側：`routing_eval` の `--twins` は、経路の辺の双子をすべて出す（`twin_lines` の要素は辺と双子の組ごと）。

全国の `topology.bin` を作り直した（`graph.bin` は不変。旧ファイルは `topology.v1.bin`・`topology.v1.audit.json`・`p3.v1.log`）。
