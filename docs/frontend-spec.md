# フロントエンド機能仕様

## 1. 目的と責任範囲

React / TypeScript / Vite / MapLibre GL JSで、出発地と目的地を指定し、最短時間経路と事故履歴を考慮した経路を比較する。API契約は [api/openapi.yaml](api/openapi.yaml)、集計の意味は [api/behavior.md](api/behavior.md) に従う。生成されたTypeScript型を使用し、リスク集計・候補選定をフロントで再計算しない。条件の自動緩和は行われない。

機能の根拠は [spec-decisions.md](spec-decisions.md) と関連する決定文書。`app/` はデモ、`backend/`・`frontend/` は誤って作成された実装であり、仕様の根拠にせず変更しない。住所選択、地図指定、条件指定、2経路比較、全候補一覧、事故点表示、警告を扱う。GPSによる出発地設定・ナビA＋B＋模擬走行、PWA、出発日時の指定、曜日区分、条件の自動設定は移行追加。ナビの利用者決定と委任判断は [navigation-delegated-decisions.md](navigation-delegated-decisions.md) で区別する。デモUIのLeaflet、配色、線幅、装飾は移植要件ではない。

**本書は機能だけを規定する。色・フォント・余白・アイコンの絵柄・線の見た目・細かいレイアウトは決めない。** 後のデザイン作業で決定する。画面を操作可能にする最低限の意味構造だけを作り、装飾を持たない最小コンポーネントを基本にする。

## 3. 状態モデルと操作フロー

住所入力の文字列と確定座標を別に持つ。「住所が入力済み」だけでは確定としない。各地点はinputText、selectedPoint（lat/lonとlabelまたはnull）、検索候補、検索状態、入力revisionを持つ。

全体は次を持つ。

- 選択対象
- 出発日時（mode: now/custom、custom時の日時）
- 条件（period/day_type/weatherはそれぞれ値とsource: auto/manual。weatherのautoには取得状態と取得元情報を付ける）
- 条件取得状態と世代番号
- ルート状態、結果
- health状態、地図状態、GPS状態、事故点表示状態
- ナビ状態（停止/測位待ち/進行中/精度不足/照合保留/逸脱/一時停止/再検索中/到着）、位置源（実機/模擬）、選定種別（fastest/safest）、経路ID・応答世代・ナビ世代、直近測位と進捗、通知済み区間ID集合、判定タイマー

保存先はReact等のページ内メモリのみ。

| イベント                         | 必須挙動                                                                                                                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 初回表示                         | `/api/health` を1回呼ぶ。出発日時=現在で `/api/conditions` を地点なしで呼び、period/day_typeを自動設定する。weatherは地点未確定のためすべて。地図初期化を並行してよい。空の比較案内を表示 |

### 抑止と競合の制御

ルート検索中は条件入力、出発日時、地点変更、住所検索、GPS、二重送信を抑止する。地図のパン/ズームや比較と無関係な操作は可能。

住所検索中は当該検索ボタンを抑止するが、編集は可能。条件取得中は経路検索ボタンを抑止するが、各条件の手動変更は可能。手動変更した項目は応答到着時に上書きしない。

住所検索要求・条件取得要求ごとにsequenceとrevisionを保持し、遅い旧応答（エラーも含む）を反映しない。地点確定・条件変更・出発日時変更・経路検索開始・unmount時は不要な通信をabortする。abortが間に合わなくても応答世代照合で棄却する。ボタンの再有効化も現行要求の完了時だけ行う。

経路応答は取得時の入力snapshotと世代番号に対応付ける。地図がAPIより遅く初期化されても、最新結果を後から描画できるようにする。healthのdataset_idと後続routeのdataset_idが違う場合はrouteを表示しつつhealthを1回更新する。事故点のID集合を別データ世代へ持ち越さない。

ナビ中（一時停止・精度不足・逸脱・再検索中を含む）は比較入力の編集・地図による地点設定・住所検索・単発GPS取得を抑止する。変更する場合は安全な場所でナビを終了してから行う。地図の閲覧とナビ停止は可能。専用再検索は7.6の一つの操作として入力と結果を入れ替える。経路結果解除・経路切替・unmount・到着ではナビ世代を進め、旧watch/タイマー/音声を破棄する。

## 4. 出発日時と条件の自動設定（移行追加）

旅行計画など将来の移動の比較を想定し、出発日時・時間帯・曜日区分・天候を変更可能とする。既定は「現在の時間帯・曜日区分と、該当地域の現在の天候」とする。

### 出発日時

- 「現在」と「日時指定」を選択できる。日時はAsia/Tokyo固定で扱い、ブラウザのタイムゾーンに依存しない。
- 「現在」の基準時刻は条件取得のたびにその時点の時刻とする。表示には取得時の基準時刻を示す。
- 過去の日時も指定できる。現在より15分を超えて前の日時では天候を自動取得せず（`weather_status=past`）、天候はすべてにして手動選択を案内する。
- 出発日時はroute APIへ送らない。routeへ送るのはそこから決まったperiod/day_type/weatherだけである。

### `/api/conditions`

時間帯・曜日区分・天候の自動値は `/api/conditions` から取得する。区分境界と祝日判定を事故集計側と一致させるため、フロントでは計算しない。

```
GET /api/conditions?datetime=<ISO8601, +09:00>[&lat=..&lon=..]
→ {
  period: <時間帯値>,
  day_type: <平日|休日>,
  day_type_reason: "土曜" | "日曜" | "祝日：<名称>" | "振替休日" | "国民の休日" | "年末年始" | "平日",
  holiday_table_covered: boolean,
  weather: <晴|曇|雨|霧|雪> | null,
  weather_status: "ok" | "no_location" | "out_of_range" | "past" | "unavailable",
  weather_source: { provider, target_time, kind: "current"|"forecast" } | null
}
```

具体的な型はOpenAPIで確定する。フロントの扱いは次のとおり。

- 両地点が確定していなければlat/lonを付けない。その場合、天候は `weather_status=no_location` となる。
- 両地点が確定したら、2地点の中点を**小数2桁（約1km）に丸めて**送る。2地点の直線距離は最大30kmであり、中点1点で地域を代表させる。
- 現在との差が±15分以内の日時（出発日時=現在を含む）では天候は現況値、15分を超えて先の日時ではその時刻の毎時予報になる（behavior 9章）。予報範囲外の日時は `out_of_range` として天候をすべてにする。フロントは境界を自分で判定せず、応答の `weather_status` と `weather_source.kind` に従って表示する。
- `holiday_table_covered=false`（祝日表の収録範囲外）の場合、曜日区分は土日と年末年始だけで判定された値である旨を警告として表示する。
- 取得失敗・タイムアウト（10秒）・オフラインの場合、auto状態の項目はすべてにして、失敗と手動選択を案内する。経路検索は妨げない。自動リトライはしない。

### 自動値の表示

- 各項目について、自動値か手動値かを表示する。自動の天候には取得元、対象時刻、現況か予報かを示す（例：「自動：雨（Open-Meteo、10/31 14:00の予報）」）。
- 曜日区分にはday_type_reasonを表示する（例：「休日（祝日：文化の日）」）。
- 事故記録の天候は発生時の現場の判定であり、自動取得の天候は気象モデルの推定値である。両者が同じ尺度でないことを説明に含める。
- 天候の自動取得が使えない理由（地点未確定・予報範囲外・過去日時・取得失敗）はweather_statusごとに区別して伝える。

### プライバシー

外部の気象サービスへ座標を送るのはサーバであり、ブラウザから直接は呼ばない。座標が自サーバへ送られるのは次の2つの場合だけである。

- 両地点の確定後に行う条件取得（丸めた中点のみ）
- 利用者が行う経路検索

## 5. API通信と表示規則

APIは同一オリジンの相対 `/api/...` を使い、Accept application/json、routeはContent-Type application/json。UIタイムアウトはroute/geocode/healthが現行同様45秒、conditionsが10秒。自動リトライ、自動ポーリング、入力ごとの住所補完は行わない。health失敗は手動再確認、経路失敗は明示的再検索とする。

応答がJSONでない、必須フィールド/参照IDが壊れている場合は「応答を読み取れない」と表示し、部分的な成功として描画しない。IAPのセッション切れなどでAPIがログインへリダイレクトされた場合も非JSONの失敗として扱い、ナビを停止し、安全な場所で停止した後のページ再読込（再ログイン）を案内する。未知のerror.codeはmessageと再試行案内で扱う。codeで状態を判断し、日本語messageの部分一致で処理を分岐しない。AbortControllerによる期限超過、ネットワーク不通、HTTPエラーを区別して利用者に伝える。提供元ラベル・API説明・エラーはテキストとして描画し、HTMLとして挿入しない。

healthが503 data_unavailableなら経路検索を無効化し、データ準備中と再確認操作を示す。healthのネットワークエラーだけなら「状態未確認」として入力・手動経路検索を許す。healthは上流サービスが利用可能という保証ではない。

### 比較表示

- 「最短時間経路」と「事故考慮経路（取得候補内）」の2つの意味を常に表示する。事故考慮は全道路網の最適解という表現にしない。
- safest_idがnull（全候補で該当事故なし）の場合は事故考慮経路を描画せず、reasonで事故を考慮した経路を選んでいない旨を伝える。トップレベルのextra_minutesと削減率はnullなので、0や「同じ経路」に変換しない。
- 各経路について次を表示し、単位を明示する。表示丸めで選定や許容内外を再判定しない。
  - duration：分（小数1桁）
  - distance：km（小数2桁）
  - extra_minutes：分（小数1桁）
  - 事故件数、死亡/負傷事故件数、死者/負傷者の人数（天候を問わない集計）
  - 天候指定時はweather_match（指定天候に一致する事故の同じ5項目）。weather_match=null（天候すべて）と0件を区別する
  - weighted_risk、risk_per_km
- risk_reduction_percentがnullなら「算出できません」と理由（最短時間経路の基準リスクが0、または事故考慮経路なし）を表示し、0%や100%へ変換しない。数値なら小数1桁の%表示。
- reason、全warnings、risk_noteを省略しない。条件は自動解除されないので、effective_conditionsは要求条件の正規化値として表示する。天候指定は件数を減らさないことを説明に含める。雨・霧・雪を指定した場合だけ一致事故を重く数え、晴・曇では天候一致の集計（weather_match）だけが変わる。
- 適用条件の表示に、要求時の出発日時と、各条件が自動か手動かを含める。
- 集計半径radius_m（72m）と距離重みのσ（distance_weight_sigma_m）、候補数、aggregation_ms（表示は整数ms可）、対象データ年を確認できるようにする。aggregation_msを検索全体の通信時間と表示しない。
- 最短時間と事故考慮が同じIDでも2つの選定の意味を表示し「今回は同じ経路」と伝える。別々の改善があるように見せない。

| オフライン | 再訪はアプリシェルと説明のみ。既存ページのメモリ内ナビは地図描画・測位が使えれば継続可（7.8）。新しい住所・条件取得・経路検索は不可。復帰後の自動再送なし |
| ナビの測位待ち/精度不足/照合保留 | 原因・精度・最後の位置時点を表示。進捗を更新停止にし、接近・到着を判定しない |
| ナビの逸脱 | 逸脱を表示し、安全な場所で停止後の再検索を案内。自動検索しない |
| ナビの一時停止/非表示から復帰 | watch/模擬/音声停止。前回位置と停止状態を表示し明示再開 |
| 権限拒否/音声不可/Wake Lock不可 | 拒否理由と手動設定/模擬、画面通知、画面消灯時停止をそれぞれ案内。反復要求なし |
| 再検索中/失敗 | 二重送信抑止、旧結果を解除。失敗時は停止して明示再試行 |
| 模擬走行中/到着 | 実際の現在地でない旨と倍率/停止状態を常設。到着時は位置源と音声を停止 |

API説明文字列は将来変わり得る。キーボードで入力・候補選択・検索・表示切替・出発日時と条件の変更を操作でき、ラベル、押下状態、処理中状態、自動/手動の区別、エラー通知は支援技術にも伝える。住所検索による代替操作を用意し、地図操作だけを必須にしない。

## 6. MapLibreのデータ・レイヤー契約

経路の `geometry` はLineString、事故と高リスク区間はFeatureCollectionなので、座標反転や再集計なしでGeoJSON sourceに設定する。MapLibreのsource更新機能を使用する（[公式GeoJSONSource](https://maplibre.org/maplibre-gl-js/docs/API/classes/GeoJSONSource/)）。以下のIDをフロント内の標準とし、データと描画スタイルを分離する。

| Source / layer ID                         | 型・内容                                              | 更新条件                                          |
| ----------------------------------------- | ----------------------------------------------------- | ------------------------------------------------- |
| route-fastest / route-fastest-line        | fastest.geometry、line                                | 経路成功時と結果解除時                            |
| route-safest / route-safest-line          | safest.geometry、line                                 | 同上。同一IDなら重なりを含めて2選定の意味を伝える。safest_idがnullなら空 |
| route-high-risk / route-high-risk-line    | 選定経路（1〜2本）のhigh_risk_sectionsを連結したFC、line | 同じ経路は一度だけ追加                            |
| route-accidents / route-accidents-point   | 選定経路（1〜2本）の事故FCをidで重複排除したFC、circle等の点 | 応答/表示切替。候補順で最初の点を採用             |
| origin-marker / dest-marker               | それぞれの確定座標                                    | 地点確定・解除                                    |
| current-location / current-location-point | 実機/模擬の直近位置。正常照合時は射影位置、逸脱/保留時は実測位置 | 測位・状態更新・終了。GPSと模擬の区別を表示 |
| current-accuracy / current-accuracy-fill | 未補正の測位を中心としたaccuracyの円。射影位置とは区別 | 測位・終了。古い測位は時点を表示 |
| navigation-route / navigation-route-line | 選んだ1本のgeometry。比較レイヤーとはナビ状態で区別 | ナビ開始・再検索成功・終了 |
| navigation-alert / navigation-alert-line | 通知中区間のstart_m〜end_mに対応する経路部分。0長なら点の代替表示 | 通知・通過・停止。ナビ用区間から描画し上位100件を改変しない |

背景地図→比較/ナビ経路→表示用高リスク区間/ナビ通知区間→事故点→精度円/地点・現在地マーカーの論理順で、操作に必要なマーカーが隠れないようにする。経路間の重複を判別する表現はデザイン段階で決める。色の指定はしない。地図上の役割は凡例/テキストでもわかるようにする。

事故点のポップアップは次を表示する。

- 死亡/負傷区分（deaths>0）
- 発生日と曜日区分（平日/休日）
- 時間帯、天候
- 死者/負傷者人数
- source_year

dateはYYYYMMDD整数から年月日へ表示変換し、source_yearと混同しない。事故点の曜日区分は応答の値を表示し、フロントで日付から判定しない。高リスク区間の操作でseverity_weight（深刻度の合計。距離減衰・天候倍率なし）と対象経路を確認できる。地図上の点数は重複排除後なので、各経路のpoints_shownの単純合計と異なってよい。集計値は変更しない。

既存source/layerを更新してMapインスタンスの作り直しを避ける。結果解除時に古いsourceデータ/ポップアップを消す。コンポーネント終了時にイベントとMapを破棄する。背景スタイル再読込時は最新source/layerを復元する。比較時のbounds計算は選定2経路だけを使い、事故点の広がりや未選定候補で勝手に範囲を変えない。ナビ中は現在地追従を初期ONとし、手動パンで解除、停止後の明示操作で復帰できる。測位ごとにfitBoundsや回転を繰り返さない。

## 7. GPSとナビ（移行追加）

### 7.1 GPSによる出発地設定

「現在地を出発地に設定」の明示操作で、`navigator.geolocation.getCurrentPosition` を1回呼ぶ。位置情報は利用者の許可とsecure contextが必要である（既存参照：[W3C Geolocation](https://www.w3.org/TR/geolocation/)）。本番はHTTPS必須。実演はCloud RunのHTTPS URL（IAP配下）で行う。

取得オプションは `enableHighAccuracy=true, timeout=10000, maximumAge=0`。GPSセンサー使用や精度を保証する指定ではない。WGS84・accuracyの単位m・有限数値・日本矩形内を検査し、成功時は出発地を「現在地」として確定する。精度は表示し、隠れた座標補正はしない。経路結果を解除し目的地を保持する。目的地があれば4章の条件取得を行う。自動経路検索・住所逆引きはしない。

PERMISSION_DENIEDは住所/地図指定を案内し、許可ダイアログを反復しない。POSITION_UNAVAILABLE、timeout、非対応、非HTTPS、日本範囲外は区別し、失敗で既存出発地を消さない。取得中の入力変更で世代を進め、取り消せない古いコールバックを棄却する。

### 7.2 ナビの開始・停止と位置源

**利用者決定（2026-10-24）**：A＋B＋模擬走行を採用する。`fastest_id` とnullでない `safest_id` に対応する経路だけから開始できる。同じIDなら経路データは共用し、選んだ種別（最短時間/事故考慮）は再検索用に保持する。全候補一覧の未選定経路には開始操作を設けない。

開始前に選定ID・navigationの非null・累積距離配列・区間参照・応答世代を検査する。L=0または地図が利用不可なら開始できず、理由を表示する。`sections=[]` は「対象区間なし」で開始可能。上位100件の `high_risk_sections` を通知に流用しない。条件と事故データは検索時点のものと表示し、ナビ中に時間帯/天候を自動更新しない。

開始操作で7.9の注意を表示し確認する。「実機GPSで開始」と「模擬走行で開始」を明確に分け、同時には動かさない。実機は開始時だけ `watchPosition` を登録し、オプションを `enableHighAccuracy=true, timeout=10000, maximumAge=1000` とする。ブラウザが更新頻度を決めるため1秒ごとの取得は保証しない。位置のたびに入力欄のoriginを更新したりconditions/routeを呼んだりしない。

- 終了・到着・経路切替・再検索開始・unmount・権限拒否・hidden/pagehideで `clearWatch`、模擬タイマー停止、発話取消、Wake Lock解放を行う。位置取得の世代も進め、遅い結果を捨てる。
- 一時停止は同じ停止処理を行うが、メモリ内の経路・最後の進捗・通知済み集合・模擬状態を保持する。現在地を「一時停止時の位置」と表示する。明示再開で新しい測位を取得し、復帰確認後に判定を再開する。
- 終了時は現在地・判定用の直近値・通知状態・模擬シードの実行状態を破棄する。比較結果を残しても、ナビ再開は新規開始になる。経路変更は終了後だけ可能。
- 実機GPSと模擬は同じ入力 `{lon,lat,accuracy,timestamp}` と時計を持つ位置源アダプタを通し、同じ進捗・逸脱・通知・到着処理を使う。実機だけの成功扱いや模擬だけの通知の近道を作らない。

### 7.3 現在地の射影と精度（委任判断・暫定値）

ナビ用距離は `navigation.projection_lat_deg` とgeometry先頭を原点としたbehavior 6章の局所平面m。元辺への射影係数tを0〜1へ制限し、対応する `vertex_distances_m[j] + t*(vertex_distances_m[j+1]−vertex_distances_m[j])` を進捗候補pとする。0長辺はt=0。球面距離やOSRM distanceをこの軸に混ぜない。

これは選んだ一本の線への幾何学的な照合であり、道路網へのマップマッチングではない。OSRM Match/Nearest等は呼ばず、[route-scoring-decision.md](route-scoring-decision.md) の不採用方針を維持する。立体交差・反対車線・並行道路の判別や走行道路の保証はできない。

| 判定 | 規則 |
|---|---|
| 測位の受理 | 有限座標・日本矩形・有限かつ正のaccuracy、前回より新しいtimestamp。未来時刻や取得後5秒超の位置は使わない。実機は端末時計と受信時刻、模擬は仮想時計で鮮度を判定する。 |
| 精度良好 | `accuracy <= 30m`。超過は「位置精度が低いため判定を停止中」。実測位置と精度円は表示できるが、進捗・通知・到着・逸脱/復帰の確定には使わない。測位なし5秒超も同じ扱いで、以前の現在地には時点を付ける。 |
| 連続性 | 初回は全経路を探索。その後は最後の確定p（初回確認中は直前の暫定p）から前後 `W=v_limit*min(Δt,30)+2*max(前回accuracy,今回accuracy)+10` mの範囲に射影候補を限定する。Δtはその基準pの測位からの秒、v_limitはwalk=3、bike=12、car=40m/s。前後同幅で戻りも許し、pを単調増加に固定しない。30秒を超える中断でも探索窓を無限に広げず、対応がなければ保留する。 |
| 交差・折返し | まず範囲内の各局所的な距離最小候補を求める。同じ頂点に接続する辺の同じpは1候補。最小横距離との差が10m以内、かつpが30m超離れた別候補があれば「経路上の位置を確認中」として保留する。曖昧でない同距離候補は前回pとの差、元辺indexの順で選ぶ（初回はindex）。近いという理由だけで別の折返し先へ飛ばさない。 |
| 初回・復帰確定 | 精度良好で一意な候補が3測位以上・5秒以上続き、横距離が `max(20m,accuracy)` 以下で確定する。初回確認中は暫定pを次の窓の基準にし、通知を出さない。確定後も飛びや曖昧さが出たら保留し、同じ確認をやり直す。 |
| タイマー | 間隔5秒超、精度不足、古い入力で連続判定をリセットする。曖昧さは射影・接近・復帰・到着の連続判定をリセットするが、精度良好な位置の全経路への横距離による逸脱判定は独立して続ける。無効入力が逸脱/到着時間を進めない。位置履歴の配列を蓄積せず、直近値・暫定候補・時点/カウンタだけ保持する。 |

照合できた位置は選定経路上のマーカーで示し、実測位置の精度円も区別して表示する。逸脱・精度不足・照合保留では実測位置を表示して経路上へ強制的に吸着させない。横距離自体は全経路への最短距離も求め、7.5の逸脱判定に使う。交差で一意に決められないことと、経路から離れたことを混同しない。

### 7.4 残り距離・時間と到着

確定pを0〜Lへ制限し、残り割合 `r=1−p/L`、残り距離=`candidate.distance*r` m、残り時間=`candidate.duration*r` 秒とする。「残り距離（概算）」「残り時間（概算）」を表示し、距離は10m単位、時間は分へ切り上げる。経過実時間をdurationから引かず、停止中は減らない。渋滞・坂・区間ごとの速度差・実速度の予測は反映しない。模擬倍速でも表示は基準の残り時間であり、倍速で割らない。

精度不足・照合保留・逸脱では最後の値を「更新停止」として示し、算出済みでなければ「—」。`p>=0.9*L` かつ `L−p<=20m`、実測位置とgeometry終点の局所距離<=30mが精度良好な3測位以上・5秒以上続いたら到着とする。到着時は0を表示し7.2の停止処理を行う。目的地入力ではなく経路終点への到着判定であることを示し、OSRMの端点と入力地点が離れる場合も到着を保証しない。

### 7.5 接近通知と逸脱（委任判断・暫定値）

ナビ用 `sections` の距離軸に沿った前方の区間を使う。通知距離Dは **徒歩80m、自転車150m、自動車300m**。代表速度約1.4/4.2/13.9m/sなら約57/36/22秒の猶予を意図した初期値であり、停止距離や安全を保証しない。精度良好・一意照合・進行中だけで判定する。

- 未通知・未通過区間について `start_m−p<=D` かつ `p<=end_m` が1秒以上隔てた2測位で続けば通知する。開始/復帰時に区間内なら同じ規則で「過去事故の参考区間にいます」。初回の位置確定時点でend_m<pの区間は既通過にし、遡って通知しない。
- 前回確定pより5m超後退した測位では接近判定をリセットし、新規通知しない。再び非後退の2測位を得たら再開する。ヒステリシスとして接近候補を解除するのは `start_m−p>D+30m`、通過済みと確定するのは `p>end_m+30m`。D超〜D+30mでは接近候補の状態を保持するが、通知に必要な連続2測位のカウンタはリセットする。通過済み状態は同じセッション内で保持する。pがend_mを超えた区間の新規通知はしない。
- 結合済み1区間につき**ナビセッション中最大1回**。通知済み集合は画面通知を出した時点で更新し、後戻り・一時停止/再開・逸脱復帰では消さない。新しい検索/新規開始でだけリセットする。0長区間も同じ距離規則で扱い、測位間で飛び越えた区間の後追い発話はしない。
- 連続した対象sidはサーバで結合済み。フロントでリスク区間を再分割・再結合しない。複数区間が同時に接近条件を満たした場合は、区間IDは各々記録し画面で件数を示し、音声は「この先に、過去事故の参考区間が続きます」の1回にまとめる。
- 音声開始間隔は**実時間10秒以上**。間隔内は画面通知のみとし、後からまとめて発話しない。発話キューは積まない。発話中に新規通知が来ても画面のみ。発話/待機は精度不足・照合保留・逸脱・停止時に取消し、失敗した通知を自動再発話しない。
- 単一区間の文言は「この先に、過去事故の参考区間があります。周囲に注意してください」。曲がる方向・車線・回避操作を指示しない。画面には「過去事故の参考情報です。現在の危険や安全を保証するものではありません」を常設する。区間なし・通過済みでも安全とは表示しない。

音声はWeb Speech APIの `speechSynthesis` を使い、開始ボタンの同期的な操作起点で日本語の短いテスト発話を試す。`lang=ja-JP` とし、取得した音声のうちja-JP（なければja）の端末内音声を優先する。日本語音声がなければ他言語へ黙って切替えず画面通知にする。voiceschangedで一覧を更新しても音声の再有効化は停車後の明示操作で行う。音声本文には座標・住所・経路名を含めず定型文だけにする。外部TTSサービスを追加しない。

非対応、音声なし、error、開始後3秒以内にonstartが来ない、または発話終了が15秒以内に来ない場合は取消して「音声を利用できません。画面通知を使用します」と表示する。端末の無音設定や出力先まではAPI成功で検証できないため、開始時に聞こえることを利用者が確認できるようにする。iOS等の利用者操作起点の制約、後続発話の可否、ja-JP音声の提供・端末内処理の保証は**要確認**。音声失敗で位置処理を停止したり、走行中の再操作を要求したりしない。

逸脱は、精度良好な位置の全経路への最短横距離が `max(40m,2*accuracy)` より大きい状態を**10秒以上・3測位以上**確認して確定する。逸脱疑いの間も進捗・接近・到着は保留する。accuracy>30mでは逸脱を断定しない。逸脱表示は新しい良好測位で復帰するまで保持し、途中の精度不足は併記する。復帰は一意の射影と横距離 `<=max(20m,accuracy)` を**5秒以上・3測位以上**確認する。異なる距離閾値と継続時間で状態の往復を抑える。

逸脱時は「経路から外れています」と「安全な場所で停止してから現在地から再検索」ボタンを表示する。自動でroute/conditionsを呼ばず、復帰後も通知済み集合を維持する。照合保留が続く場合にも停止後の同じ再検索操作を利用できる。

### 7.6 現在地からの明示的再検索

1. 安全な場所で停止して行う明示操作とする。押下時に変更前の出発日時・条件・選定種別をメモリ内snapshotへ取り、ナビ・入力・条件・routeの世代を進め、watch/模擬/音声を停止して二重操作を抑止する。現在地は最後の未補正の実機/模擬測位を使う。精度30m以下・5秒以内なら採用。古い/未取得/精度不足なら実機は当該操作内で新しい1回の測位（7.1のオプション、同じ精度条件）を要求し、失敗時は送信せず停止状態にする。模擬は停止位置から新しい仮想時刻の測位を1回生成する。射影位置をoriginに偽装しない。
2. 目的地・mode・max_detour_minと選んだ種別を引き継ぎ、新originを確定する。旧比較結果とナビデータは解除し、再検索中の操作を抑止する。取得中の終了/unmountは要求をabortし、旧世代の成功/失敗を反映しない。
3. 出発日時を「現在」にする。元がcustomなら通常の出発日時変更と同じくperiod/day_type/weatherをautoへ戻す。元がnowならmanual項目を保持する。新originへの変更なので、前回取得から15分未満でも **conditionsを必ず1回取り直す**。送る座標は新originと保持destの中点を小数2桁へ丸めたものだけ。失敗時は4章どおりauto項目をallにし、manualは維持、状態を表示する。以後の手動検索でも現在モードの15分規則を維持し、定期更新はしない。
4. その操作で確定した条件を使い通常のPOST `/api/route` を1回送る。自動リトライ・steps・特別なGPS追跡APIはない。直線20m〜30km、経路80km等の既存検証、OSRM最大3呼出し、全利用者共通1req/秒・開始間隔1050ms、35秒期限をそのまま適用する。到着付近で20m未満なら検索できない旨を示し、制限を迂回しない。
5. 最新世代の成功時は新しい同種の選定ID（fastest/safest）で同じ位置源のナビを継続し、初回の位置確認から開始する。これは7.8の非表示停止や世代無効化がない場合に限り、hidden中には開始しない。区間ID/通知済み集合は全破棄。同一IDに選ばれ直しても新世代。safest=nullなら自動でfastestへ切替えず停止し、事故考慮経路がない旨と最短時間経路の明示開始を案内する。L=0/地図不可も停止する。
6. 503 service_busy、502、期限超過、非JSON/IAP失敗では新origin・条件を保持し、旧経路を現条件の結果として復活させない。GPS/模擬は停止したまま、手動再試行だけを許す。再試行も1.から実行する。IAP再ログインは安全な場所で停止後に行い、再読込でメモリが消えることを示す。

### 7.7 模擬走行（利用者決定を委任判断で具体化）

IAP配下の本番実演でも利用できる。GPS許可は不要。選定経路上の基準位置を先頭p=0から進め、基準速度は `distance/duration` m/s、進捗距離軸の速度は `L/duration` m/sとする。**1/2/4/8倍**を選択可能、初期1倍。速度換算の違いは距離軸が異なるためで、到着による停止を考慮しない基準位置はduration秒の仮想時間で終点へ達する。共通到着判定が先に成立すれば、実機と同じくその時点で終了する。

仮想時計は実時間の進み×倍率。一時停止・非表示中は進めず、再開時に停止分を追いつかせない。仮想1秒ごとに基準位置を元geometryで補間し、揺らぎを加えた位置・accuracy・仮想timestampを同じナビ処理へ渡す。タイマー遅延による実時間5秒超の空白は一時停止し、大量の測位を一括再生しない。飛び検出・逸脱/復帰/到着・通知の連続秒数も仮想時計を使う。音声の10秒間隔だけは実時間で守り、倍速による発話の積み残しを作らない。終点では基準位置を保持した測位を続け、共通到着判定で終了する。

- 揺らぎは初期ON、半径8mの円内一様分布。uint32のseedを指定可能（初期1）、`x=(1664525*x+1013904223) mod 2^32`、各更新後 `u=x/2^32`。仮想tickごと2回進め、`r=8*sqrt(u1), θ=2π*u2`、局所平面の東西へ `r*cos(θ)`、南北へ `r*sin(θ)` mを加算する。OFFでも乱数を同じ回数進め、加算を0にする。
- 合成accuracyは常に10m。位置・仮想時計を含めて同じseed・同じ操作列なら同じ出力にする。pause/resumeは乱数状態を保持、終了/新規開始はseedから再初期化。試験fixtureではaccuracyや欠測も位置源へ注入できるが、利用画面に多数の診断設定は設けない。
- 常時「**模擬走行中（実際の現在地ではありません）**」、倍率、進行/一時停止を表示し、マーカーと音声開始時の案内でも区別する。模擬中に実機GPSを起動せず、切替には終了を必要とする。軌跡ファイルの読込/再生/保存/ダウンロードは設けない。
- 「逸脱を試す」操作で、基準位置の正の長さを持つ進行辺の左法線へ120mずらす状態を仮想20秒間付加する。辺境界では次の正長辺、終点では直前の正長辺を使う。揺らぎはその上に加える。基準進行は継続し、20秒後は通常へ戻す。別の経路部分が近い形状では逸脱にならない場合があるため、試験は並行/折返しのない直線fixtureで行う。
- 再検索は模擬位置を新originにする**実際のAPI検索**。ボタン付近に「模擬位置から条件と経路を取得します」と表示する。GPSは使わず7.6と同じ制限・失敗処理を適用。成功後は新経路先頭・同倍率・同seedから再初期化し、逸脱操作は解除する。模擬だけを動かす間はAPI呼出しなし。

### 7.8 ブラウザ制約とライフサイクル

- Screen Wake Lockが利用可能なら、明示開始/再開時に画面のロック防止を要求する。未対応・拒否・OSによる解除でもナビを利用でき、「画面が消えるとナビは一時停止します」と示す。再取得は明示再開時だけで、解除を無限に再試行しない。
- visibilitychangeのhidden、pagehideでは即座に7.2の停止処理を行う。ナビ再検索のconditions/routeが進行中ならabortし、これらの要求世代も無効化する。hidden中のコールバックは世代とvisibilityで棄却する。visible/pageshow（BFCache復帰を含む）で自動再開せず、再開操作と位置確認を必要とする。バックグラウンド追跡・Background Sync・隠れた模擬進行はしない。OSによる突然の終了時にcleanupの実行までは保証できないため、復元時も位置源を無効状態から始める。
- PERMISSION_DENIEDなら実機ナビを停止し、設定変更後の明示再開または模擬を案内。POSITION_UNAVAILABLE/timeoutは精度不足と同様に判定保留、watchの再登録ループや権限要求の反復はしない。既存watchで良好測位が戻れば位置確認から復帰できる。
- オフラインでもページ内メモリの経路・ナビデータと測位が使える間はナビを継続できる。新しい検索/条件取得は不可、再訪/再読込後は経路を復元できずシェルだけ。接続復帰でAPIを自動送信しない。これはオフライン地図/道路検索の提供ではない。
- 一部タイル取得失敗は欠落と取得失敗を表示し、手元の経路線と位置を描画できるなら継続する。WebGL/スタイル等の失敗で経路と位置が描けない場合はナビを一時停止し、新規開始不可。回復後も明示再開する。
- IAPセッションの定期確認はしない。検出されないセッション切れでは既存メモリ内処理は継続する。明示API操作時の401/403・認証リダイレクト・非JSON/CORS等は通信/認証失敗として停止し、停車後の再ログインを案内する。認証ページへ自動遷移・自動再送しない。
- SW更新はナビ状態を含めて8章の保留規則を適用する。wake/音声/測位は機種差があるため、対応可否を機能検出し、実機で確認する。

### 7.9 安全・法令・プライバシー

開始時に「過去事故の参考情報で、安全を保証しません。自動車・自転車の運転中は画面を注視せず、端末を手に持って操作しないでください。設定・再検索・再開は安全な場所で停止してから行ってください。道路標識と周囲の状況を優先してください」と表示し、確認後だけ開始する。徒歩でも歩きながらの注視を避ける案内を含める。

道路交通法の携帯電話使用等の規制と、2024年11月からの自転車のながらスマホに対する罰則を踏まえ、走行中に確認ダイアログへの返答や復旧操作を必須にしない。接近情報は短い音声と受動表示で提示し、GPS速度から「停車したので操作してよい」と判定しない。安全な場所で停止したことを操作時に利用者へ促す。条文の適用範囲・例外・最新改正・注意文の最終適否は**要確認**。今回ネットワークで法令原文の現行性は確認していない。

実機・模擬の位置、精度、進捗、限定した直近判定値、通知済みIDはページメモリだけ。位置を時系列配列として蓄積せず、ログ/分析イベント/エラー報告/ストレージ/URL/history.stateへ出さない。開始・更新・停止自体は位置をサーバへ送らない。送るのは明示的再検索（と4章の条件取得規則）だけで、単なる移動をconditions取得の契機にしない。終了・unmount・再読込でナビ状態を破棄する。再検索のため採用したoriginは入力状態としてページメモリにだけ保持し、入力解除時に破棄する。

地図追従による表示範囲は外部タイル提供元へ伝わり得る。既存の外部提供元ログ許容と自アプリの無保存は区別して説明する。音声は住所/座標を含まない定型文のみ。模擬位置にも同じプライバシー規則を適用する。


## 8. PWA（移行追加）

- `/manifest.webmanifest` にname/short_name、start_url=/、scope=/、display=standalone、192×192と512×512のインストール用アイコンを設ける。アイコンの見た目・名称の最終文言はデザイン工程で決める。アイコンは内容ハッシュ付き `/assets/` に置く。IAP配下でcookieを送るため、manifestは `crossorigin="use-credentials"` で読み込む。
- `/sw.js` をscope=/で登録し、version付きアプリシェルのキャッシュだけを管理する。初回オンライン読込後にHTML・JS・CSS・自アプリの必要アセットをオフライン表示できること。
- `/api/*`（`/api/conditions` を含む）は成功/失敗ともService Worker・Cache Storageの対象外とする。住所入力、GPS/模擬位置・進捗・通知済みID、出発日時、条件取得結果、経路、ナビ区間、事故点レスポンスをIndexedDB/localStorage/sessionStorage/URL履歴へ保存しない。Background Syncで再送しない。
- 地図タイル/スタイル/外部フォント等の外部リソースを一括保存・先読みしない。PWA化はオフライン地図/検索を意味しない。契約済み自己配信タイルのオフライン化は別要件。
- SW更新があれば利用者へ再読込可能と伝える。検索/GPS取得中およびナビ中（一時停止を含む）はskipWaiting/clients.claimによる強制切替・controllerchangeでの自動再読込を行わず、更新は待機させる。ナビ終了後に、同意した再読込時にメモリの位置・経路・条件が消えることを説明する。旧シェルcacheを更新完了後に削除し、型の異なるAPIと古いUIの混在はapi_version検査で検出する。
- インストール可能なブラウザには導線、非対応には通常Web利用を提供する。位置許可やインストールを初回表示で強制しない。対象ブラウザ/OSの厳密なサポート範囲は**要確認**。暫定受け入れは現行安定版のChromium系、Firefox、Safariで通常Web機能を確認し、PWAインストール可否は各環境の機能差として扱う。
