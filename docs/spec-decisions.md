## 確定した機能要件

以下は利用者が提示した当初の依頼に基づく確定事項。

## 確定：天候は除外条件にせず、経路評価の重み付けに使う

利用者の提案を受け、天候については当初の完全一致による絞り込みを変更する方針で合意した。

- 指定天候と一致しない事故も、経路評価の対象に残す。一致する事故の寄与を増やす。
- 時間帯・曜日区分など、天候以外の集計条件は今回の変更では変えない。
- APIは、他の指定条件を適用した経路周辺の事故について、天候を問わない事故件数・死傷者数と、指定天候に一致する事故件数・死傷者数を分けて返す。
- 指定天候に一致する事故が0件なら、一致する集計値はそのまま0件を返す。天候不一致の事故は引き続き評価対象になる。
- この方針は一致件数にかかわらず適用する。0件のときだけ条件を自動解除する処理は設けない。
- 重みの係数、計算式、経路決定への組込み方は、その後 [route-scoring-decision.md](route-scoring-decision.md) で暫定決定した（雨2倍、霧・雪4倍）。
- 2種類の集計のフィールド構成は `weather_match` として確定し、[api/openapi.yaml](api/openapi.yaml) と [frontend-spec.md](frontend-spec.md) へ反映した。

## 確定：条件に一致する事故がない場合

- 指定条件に一致する事故がない場合は、該当事故0件として返す。天候については、上記の合意により「指定天候に一致する集計値」と「天候を問わない集計値」を区別する。
- 全候補で0件であっても、条件を自動解除しない。時間帯・曜日区分の絞り込みを維持し、天候についても一致集計の条件を勝手に変更しない。
- 既存案の `api/behavior.md` 第7節にある条件の自動緩和は採用しない。
- PR #1には天候→曜日区分→時間帯の自動緩和が記載されているが、今回の「0件として返す」という個別合意と不一致である。統合時は自動緩和を行わない仕様に整合させる。
- この決定だけでは、事故0件の場合の経路選定方法や表示文言までは確定しない。それらは別途検証中の範囲に属する。

## 確定：死傷者数の集計範囲

- APIで返す死傷者数は、選択した移動手段が関わる事故の「事故全体の人数」を合計する。
- 例えば、自動車で検索した場合、自動車と歩行者の事故では歩行者側の死傷者も含める。
- 選択した移動手段と一致する当事者だけの被害人数としては扱わない。
- この合意は人数の集計範囲に関するもの。死者・負傷者に与える経路評価上の重みは別途検証の対象。

## 確定：座標・日時が不正な事故レコードの取り込み

- 座標や日時が欠損・不正な事故レコードは、その行を除外する。
- 不正な行があっても、残りのデータで前処理を続ける。
- 除外件数と原因を開発者向けに記録する。原因の例は、緯度・経度の空欄、存在しない日付など。
- この合意は行単位の座標・日時の不正に関するもの。ファイルを読めない、必須列がない、全行が除外された場合などの扱いは、この合意だけでは確定しない。
